# Coordinator QA: earthdata-varinfo

Decision: admit as a standalone NASA EOSDIS Python package. The Luna review is in `nasa-luna-005-03.jsonl`; this note records independent product, license, year, and scope checks.

- Government provenance: the exact [repository README](https://github.com/nasa/earthdata-varinfo) says the package was developed as part of NASA EOSDIS. NASA's [NTRS record](https://ntrs.nasa.gov/citations/20230017964) names the tool and documents its use in the GSFC data system; the report identifies Goddard Space Flight Center as acquisition source.
- Public source: NASA's [public Earthdata source repository](https://git.earthdata.nasa.gov/projects/PREFIRE/repos/earthdata-varinfo/browse?at=86b4941f597) and the current [NASA GitHub repository](https://github.com/nasa/earthdata-varinfo) expose the Python package, tests, docs, and examples without credentials.
- Eligible license: the exact current repo [LICENSE](https://github.com/nasa/earthdata-varinfo/blob/main/LICENSE) is Apache-2.0. The older public Bitbucket root snapshot at commit `86b4941f597` shows no top-level LICENSE file; the GitHub migration history's first license-bearing commit is [c2a32d1](https://github.com/nasa/earthdata-varinfo/commit/c2a32d14dc7b5952b555249b37476ca040a9da33), dated 2023-06-09. PyPI's first versioned package, [1.0.0](https://pypi.org/project/earthdata-varinfo/1.0.0/), was released 2023-06-21 and declares Apache. Therefore 2023 is the earliest defensible public licensed-source year; the earlier unlicensed public code is not counted as an open-source release.
- Primary evidence/notability: NASA's [2023 GSFC poster](https://ntrs.nasa.gov/citations/20230017964) describes this exact tool generating thousands of CMR-compatible UMM-Var records, notes 7,000+ variables published from roughly 58 GES DISC collections, and connects the records to variable-level search and subsetting. The repo provides installation, API, examples, tests, and current package distribution.
- Agency/geography: NASA EOSDIS/GES DISC at Goddard Space Flight Center, Greenbelt, Maryland. The implementation includes contractor contributions; catalog attribution is to the NASA system that developed and operates the package, not a claim that every contributor is a civil servant.

Product boundary: this is the variable-metadata extraction and generation package, not CMR itself, the Earthdata Search application, or the downstream Harmony subsetter.
